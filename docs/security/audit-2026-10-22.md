## Executive Summary

The remediation worked. Of yesterday's 53 findings, **19 are verified fixed in code, 17 are partially fixed, 16 remain open, and 1 (EAG-SEC-041) remains not-reproduced. Zero regressions were found**, and Codex's disposition document proved accurate in every case the streams checked — including its admissions of what it did not finish.

Both live exploit chains from yesterday are dead and verified dead in code: the cross-class leaderboard email disclosure (015) and the HTML-runtime teacher-token-theft chain (031). The authentication layer was rebuilt to a genuinely sound standard (throttling keyed per-account *and* per-source, generic errors, dummy bcrypt, token absolute/idle expiry with session caps, versioned admin password hashing). The supply chain is now hash-locked end-to-end, and Stream D OSV-queried all 38 locked packages at their exact locked versions: **zero known vulnerabilities**.

The remaining risk is concentrated, and it is the same three items identified last night, unchanged in kind:

1. **EAG-SEC-030 (High) — runner isolation.** Student JavaScript still runs behind only the Node `vm` realm, as the server user, with no OS containment. Student Python has strong in-process policy plus Landlock filesystem confinement, but Landlock here has no network ruleset — network denial rests on the in-process layer for both runners. A sandbox escape remains low-likelihood and total-impact.
2. **EAG-SEC-025/027 (High) — erasure and recording retention.** Account deletion is now *safe* (no orphans, no false success, retryable) and reaches 8 of 24 enumerated data stores — but a fulfilled deletion still leaves assignment submissions, notebooks, development recordings, network-lab progress, and challenge scores behind. Keystroke recordings still have no time-based expiry.
3. **EAG-SEC-014/016/019 (High/Medium) — plaintext at rest and unencrypted backups.** Identity data and accommodations remain cleartext (file permissions improved via umask 0o077); wiki backups remain unencrypted, accumulating, and unrotated.

Ten **new findings** were identified, all Low or Informational — polish items on the new controls, not holes (the most notable: NEW-A-01, one teacher endpoint that PR #190's socket-revocation machinery missed; NEW-B-01, PR #190's wiki audit ledger is keyed by staff email and never expires).

**PR #190's new surface introduced no new vulnerabilities.** Wiki-manager accounts are the most strictly validated role in the system; audited recovery is fail-closed; classroom session revocation is genuinely strong (server-side socket disconnects plus emit-time revalidation).

## Deep-dives

### EAG-SEC-025/026 — deletion is now honest, still not complete

`_delete_user_by_email` (app.py:4619) was rebuilt properly: preflight before mutation, disable-first, a retryable `AccountCleanupError`, and no false success reports. Deleting an account now reaches **8 of 24** enumerated stores: the `users.json` record, tokens/sockets, class rosters, **accommodations (new)**, workspace + Trash, provenance sidecars, tool storage — and owned classes now *block* deletion (409) instead of orphaning.

It still does **not** reach: assignment submissions (JSON + revision files), development-recording databases and bindings, notebooks + the practice-queue journal, network-lab progress (which embeds plaintext email and grades), `challenge_scores.json`, classroom signals/events, wiki bookmarks/analytics, sign-in events, or copies inside peers' workspaces. Class deletion is strong on assignments and lesson plans (both now fail-closed) but leaves the class's notebooks, network data, wiki class features/bookmarks, and signals bucket behind.

Practical meaning: if a parent or the school ever requires a student's records to be deleted, the delete button now tells the truth about failing — but a "successful" deletion still leaves the student's work, grades, feedback, recordings, and notebooks fully readable in the stores above. Codex's "Partial" disposition for 025/026 is accurate; the code's own docstring now admits the gap.

### EAG-SEC-030/045 — containment today, precisely

**Python:** strong in-process policy (locked module set including all of `asyncio`; an audit hook blocking socket/exec/kill/dlopen events) **plus Landlock applied on every run** (sandbox_worker.py:1145) — but the Landlock ruleset is filesystem-only (no `handled_access_net`), so there is **no OS-level network containment**; network denial rests entirely on the in-process layer. No UID separation, no seccomp, no network namespace. A policy escape keeps the filesystem confinement but gains unrestricted network egress as the server user.

**JavaScript:** unchanged from yesterday and the weakest point in the system. The `node:vm` realm (well-built: code generation off, frozen bridge, no host objects) is the *only* barrier — no Landlock, no namespace, no UID separation; Node runs as the server user with post-spawn `prlimit` only. A `vm` escape yields full filesystem and network access as the server account: all workspaces, all app data, and LAN services including the unauthenticated Ollama endpoint. Likelihood low, impact total.

### EAG-SEC-002 — the one decision that is purely the owner's

Everything the code can do about the LAN edge has now been done: the login endpoints behind the direct port are throttled per-account and per-source, errors are generic, and timing is equalized with dummy bcrypt. What remains is topology: production still serves Werkzeug on 0.0.0.0:8000, so any device that can route to the LXC can bypass Cloudflare entirely and talk to that hardened-but-direct endpoint. Binding loopback (if the tunnel is the only intended path) or firewalling 8000 to the classroom VLAN closes it. Relatedly, the production LXC's Node still needs upgrading to the 24 LTS line that CI already tests (the launcher accepts ≥18 and warns below 22 as EOL).

## PR #190 — new surface assessment (no new vulnerabilities)

- **Wiki manager accounts:** the most strictly validated role in the system — its own token store and header, a fresh-record check on every request, cross-store token confusion tested and rejected, admin-only creation with the role taken from the URL path, never from client input. One operator note: the app grants wiki managers *publish* rights by design; a drafts-only rule for any manager account is policy, not something the app enforces.
- **Audited recovery (wiki_history.py):** fail-closed — if milestone capture fails, the edit is refused (503). Audit records carry actor/action/status only, survive rollback, and both history listing and restore are admin-only, restore double-gated.
- **Classroom session revocation:** logout, disable, bulk actions, deletion, and password reset all disconnect sockets server-side; a patched `socketio.emit` re-validates class-room recipients at emit time without refreshing idle timers. One caller was missed — see NEW-A-01.

## Recommended priorities (in order)

1. **EAG-SEC-030** — OS-level isolation for the JS runner first (dedicated UID + network namespace or equivalent), then Python network containment (Landlock networking rules or netns).
2. **EAG-SEC-025 + 027** — one data-lifecycle pass: extend deletion to the remaining 16 stores (submissions, recordings, notebooks, network data, challenge scores first) and give recordings a time-based expiry.
3. **EAG-SEC-002** — operator decision: bind loopback or firewall 8000; upgrade the production Node to 24 LTS at the same maintenance window.
4. **EAG-SEC-008 (operator, minutes)** — run Codex's dormant-password migration tool in production (dry-run first) so legacy plaintext verifiers actually disappear; this converts a "partial" to "fixed" with no code.
5. **EAG-SEC-014/016/019/029** — the encryption bundle: identity/accommodations at rest, encrypted wiki backups with rotation, and an encrypted off-host backup with a tested restore.
6. **EAG-SEC-038** — pseudonymous external-grading identifiers before the external mode is used with real rosters.
7. **NEW-A-01** — route the teacher toggle (and session-cap eviction) through the same revocation helper as every other caller. Small fix, closes the one revocation gap.
